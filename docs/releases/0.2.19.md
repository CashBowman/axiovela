# 0.2.19: query efficiency

This release reduces avoidable generated text without changing the selected model, reasoning setting, access mode, panel layout or verification requirements.

- Direct API connections support `edit_file`: replace one unique exact passage instead of regenerating a complete file. Stale or ambiguous matches fail; unrelated text is preserved. Previous manuscript files are saved under `writeups/backups/`; other edited files use `.edit-history/`. Native CLI patch tools remain available.
- Assistants prefer focused changes and concise change summaries. Substantive answers, exact mathematics, citations, provenance and required panel updates remain part of the task. No fixed output cap or weaker model is imposed.
- File edits are bounded to 1 MB and committed atomically. An external editor can still race a tool edit; this is not a cross-process file lock.

The choice follows [OpenAI latency guidance](https://developers.openai.com/api/docs/guides/latency-optimization) and [Anthropic latency guidance](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-latency): reduce unnecessary generation and prompt content. Actual time saved depends on the provider, model and task; no live latency or billed-token reduction is claimed.

Built locally without GitHub build jobs. Linux x64 launch validation is performed locally. Other platform/hardware packages are cross-built and payload-checked; native execution remains pending. Windows installers are unsigned; Mac bundles are freshly ad-hoc signed without Apple notarization. Install manually, preserving project folders and application data.
