# Local runner backend

The Vite UI talks to the Node service at `http://127.0.0.1:8787`. Start both development processes with `npm start`, start the service alone with `npm run backend`, or install `axiovela` with `node scripts/install.mjs` to serve the production UI and API together. The legacy `ml-workbench` alias remains available. With no saved or configured root, the service starts in an unselected state and does not create an example project.

## Safety contract

- `GET /api/commands` is the command manifest; only `seed-matched-comparison` is enabled by default.
- `POST /api/approvals` returns a short-lived, project-bound approval token and the exact executable, arguments, working directory, and declared writes.
- `POST /api/runs` requires that token. The workflow is started without a shell, with a fixed Node script, `cwd` set to the project root, and `NO_NETWORK=1`.
- `GET /api/runs/<id>` provides status, progress, logs, exit information, and artifact paths. `POST /api/runs/<id>/cancel` terminates the process group.
- `POST /api/cli-guide` accepts a bounded `{message, attachment?, format?}` payload and returns deterministic workflow guidance plus a UI route. It reads only the run ledger; it never executes a command, invokes an agent, writes the attachment, or sends it to a model provider.
- `GET /api/project` describes the active project and its manifest, source inventory, discovered runs, metrics, and displayable artifacts. `POST /api/project/open` accepts `{path, create, initializeGit}` and switches the service to any local directory when no run or assistant job is active; conflicting activation requests return `409` rather than waiting. Git status is shown only when the project itself is the repository root, never when it merely lives below another repository.
- `POST /api/artifacts/upload` accepts a bounded base64 PNG, JPEG, WebP, or SVG, decodes it with Sharp, and writes a unique normalized PNG below `artifacts/figures/`.
- `GET /api/artifacts/file?path=...` serves only supported files below `artifacts/figures/` or `exports/`; project-root traversal is rejected.
- `GET /api/assistant/capabilities` returns version 3 connection catalogs, model IDs, supported efforts, runtime defaults, per-role preferences, permission modes, and Pi + Herdr Agentic mode readiness. Add `?refresh=1` to bypass the project-scoped 60-second catalog cache. Authentication configuration is never returned. `PUT /api/assistant/preferences` accepts `{role, selection: {adapterId, modelId, effort}}`; role is `experiment` or `writing`, and empty CLI model/effort values use runtime defaults (APIs require an explicit model). Invalid model/effort combinations are rejected, and active tasks block preference changes with `409`.
- `GET /api/assistant` returns the latest 30 durable project-scoped chat jobs and a conversation summary list. `?role=writing` or `?role=experiment` filters jobs; `?conversationId=…` returns a complete conversation, and `?allConversations=1` returns all stored jobs. `POST /api/assistant/conversations` accepts `{role}` and creates an empty saved conversation. `POST /api/assistant` accepts `{message, attachment?, permissionMode, agenticMode?, role?, selection?, conversationId?, newSession?}` and starts a turn through the selected CLI or direct API connection. Defaults preserve old callers. `agenticMode: true` is restricted to the experiment role, Pi, Full access, and a compatible running Herdr server; agentic and ordinary turns never reuse the same native session. `GET /api/assistant/<id>` polls it and `POST /api/assistant/<id>/cancel` stops its process group. Native thread IDs persist per conversation; `newSession: true` deliberately starts a new saved conversation. Conversation selection is project- and role-bound. Existing job records without a conversation ID appear in one legacy conversation per role. Recent context handoffs include failed requests so follow-ups do not silently lose them. Codex archive recovery uses `thread/unarchive` followed by resume, retrying only a rejected start and never a partially executed turn. Records include requested `selection`, runtime-reported `effective` model/effort, sanitized Pi `usage`, and run-scoped `agenticActivity` when applicable. Access semantics are connection-specific; consult the capability modes and provider guide. Explicit `create a project under … called "…"` requests activate a Git-initialized directory before launch. Poll responses expose only sanitized activity labels, Herdr worker names/states, and recognized user-facing assistant text, never raw stdout/stderr, session paths, transcripts, or tool payloads. See [assistant configuration](model-tools.md) for limitations and recovery.
- Full mode is intentionally unrestricted because this is a loopback local tool. The server requires a loopback address and validates the Host header on every request. Browser requests with an `Origin` header are rejected for reads and writes unless the origin is in `WORKBENCH_UI_ORIGINS`; requests without an `Origin` header remain available for explicit local CLI use. Bodies must use `application/json` and contain an object (invalid media types return `415`, oversized bodies `413`). Known credential paths and symlinks below the selected project root are rejected by ordinary project file operations. Do not expose the backend to a network or use full mode with untrusted prompts. Git push approvals are single-use and bound to the previewed project. Git push is disabled unless `WORKBENCH_ENABLE_GIT_PUSH=1` is explicitly set in a reviewed checkout.
- A fair project request gate keeps each project-scoped read or mutation on one immutable active root for its entire request, including slow body uploads. Project activation waits for earlier operations; queued operations resume against the new root. Run approvals cannot cross that boundary and return `409` after a root switch. While a launched run or assistant job remains active, another project activation also returns `409`.

## API shapes

Requests return `{ kind, status, ... }` on success and `{ error: { code, message } }` on failure. A run record has `id`, `status` (`running`, `complete`, `failed`, or `canceled`), `progress`, `logs`, `startedAt`, `completedAt`, `exitCode`, and `artifacts`.

Write-up source (`GET /api/writeups/source?format=latex|markdown`) loads the conventional AI-written source from `writeups/main.*` or the exported `writeups/research-writeup.*` fallback.
`PUT /api/writeups/source` accepts `{format, source, expectedSource?}` and atomically saves `writeups/main.*`. A mismatched `expectedSource` returns `409` without replacing the document.
Write-up export (`POST /api/writeups/export`) accepts `{format: "latex"|"markdown", draftText, includedVisuals}` and writes matching source copies to `writeups/` and `exports/`.
Full document rendering (`POST /api/writeups/compile`) writes `writeups/main.tex`, safely resolves project figures referenced by `\includegraphics` or `\includesvg`, converts SVG/WebP and stages other supported formats in `writeups/.render-cache/`, injects `graphicx` into the private render source when needed, compiles with Tectonic, and returns the served `exports/main.pdf` URL. This avoids shell escape and does not require Inkscape for project SVG figures. Compilation errors return a concise diagnostic, source line when available, remediation hint, and durable log path. If Tectonic is unavailable, the app opens a setup dialog; install the local engine with `npm run setup:latex` or set `WORKBENCH_LATEX_PATH`.
The older equation-only endpoint (`POST /api/writeups/render`) remains for API compatibility and returns server-rendered KaTeX fragments.

Provider configuration: `PUT /api/assistant/connections/:id` accepts `{apiKey?, clearKey?, endpoint?}` for API connection IDs. Keys are saved in private OS app configuration, never echoed; endpoint is for compatible APIs only. Explicit API models are required. Permission modes vary by connection; see [provider guide](model-tools.md).

Chat documents: `POST /api/assistant/render` accepts `{format: "latex"|"markdown", source}` and returns a separate chat source/export path and view URL. Markdown HTML includes offline math fonts and is served with a sandbox CSP. Full LaTeX uses Tectonic. Chat renders never overwrite the main paper.

Datasets: `GET /api/datasets` returns the project catalog. `POST /api/datasets` accepts `{sourcePath, projectRoot?}` for a regular local file or folder without a size cap. Legacy `{name, data}` base64 JSON requests remain bounded to 10 MB decoded; current clients use `POST /api/datasets/upload?name=...&folder=1&projectRoot=...` with streaming `multipart/form-data`. Omit `folder=1` for a single file. Each `files` part carries a percent-encoded filename (folder-relative path in folder mode). Multipart transfers have no application size cap and reject unsafe paths and duplicate destinations. `projectRoot`, when supplied, must match the active project. Folder imports preserve paths and report skipped credential files/links. Successful imports create independent workspace copies; failed transactions remove partial copies. `GET /api/datasets/:id/preview` returns up to 64 KB of supported text or file/folder metadata. `POST /api/datasets/:id/remove` unregisters without deleting files. Transfers share the project-switch gate, retain origin/session checks, and time out after two minutes of inactivity rather than imposing a total transfer deadline.

Project summaries include `datasets`, optional `research` from `research/summary.json`, and human figure metadata from `artifacts/figures/metadata.json`. Native runs expose `cancellable` only for live backend-owned processes. See [presentation contracts](research-workspace.md).

Bibliography (`GET|PUT /api/bibliography`) reads, validates, and saves the project-root `references.bib` library. LaTeX documents use BibTeX/natbib citation keys; Markdown uses Pandoc citation syntax and resolves the same keys in the main editor's live preview.

Infrastructure (`GET|PUT /api/infrastructure`) reads or validates `config/workbench.json`. Git is the collaboration layer; local, SSH, and Slurm-over-SSH are the compute profile types. Native, MLflow, and W&B offline adapters are discovered and normalized to the portable `workbench.run/v1` contract in `docs/workbench-run.schema.json`. Secrets are intentionally not part of the configuration schema.

`POST /api/assistant/agentic/enable` accepts `{projectRoot}`. It refreshes Pi discovery, starts an installed stopped Herdr server, and returns `{pi, agentic, projectRoot}` after readiness. Missing prerequisites, incompatibility, or startup failure return HTTP 409 with `error.details.agentic` for the setup dialog. It never installs tools or starts model requests, rejects stale projects and active assistant jobs, and uses the normal origin/session checks and project gate.
